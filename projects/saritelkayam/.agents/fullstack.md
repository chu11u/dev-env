## Task Queue

### Phase 2 Tasks (execute in order)

1. **Design Prisma schema**
   - Models: Post (id, title, slug, content, excerpt, featuredImage, status, publishedAt, createdAt, updatedAt)
   - Author (id, name, email, avatar, bio)
   - Post-Author many-to-many relation
   - Enum for status (draft, published)
   - Timestamps with defaults
   - Unique constraints on slug

2. **Create backend infrastructure**
   - `backend/package.json` with Prisma, Express (or just Prisma client + server)
   - `backend/lib/db.ts` — Prisma client singleton (prevent multiple instances in dev)
   - `backend/server.ts` — API server that serves routes

3. **Build API routes**
   - `GET /api/blog/posts` — List published posts (public)
   - `GET /api/blog/posts/[slug]` — Single post by slug (public)
   - `GET /api/admin/blog/posts` — List all posts including drafts (auth required)
   - `POST /api/admin/blog/posts` — Create post (auth required)
   - `PUT /api/admin/blog/posts/[id]` — Update post (auth required)
   - `DELETE /api/admin/blog/posts/[id]` — Delete post (auth required)
   - `POST /api/auth/login` — Admin login

4. **Build markdown content pipeline**
   - On post save: write markdown file to `content/posts/[slug].md`
   - Frontend blog pages read markdown files directly (static)
   - Frontmatter: title, date, excerpt, featuredImage, author, tags
   - Body: markdown content

5. **Build admin CMS UI**
   - Admin dashboard — Overview of posts, quick stats
   - Post list — Table with title, status, date, actions
   - New/Edit post form — Title, slug (auto-generated), content (textarea or markdown editor), featured image, status toggle, publish date
   - Simple authentication (password-protected admin area)
   - Use design system UI components

6. **Create seed blog content**
   - 3 sample blog posts about beauty/cosmetics topics
   - Written in markdown format
   - Include frontmatter with all fields

7. **Build frontend API client**
   - `frontend/lib/api.ts` — Typed API client for admin CMS
   - Functions: getPosts, getPost, createPost, updatePost, deletePost

## Output Expectations

- Admin CMS allows CRUD of blog posts ✅
- Markdown files are written to disk on save ✅

## Constraints

- Admin auth: Simple password protection (env variable), not full OAuth
- Blog storage: Markdown files in `content/` directory (not database-only)
- Database: PostgreSQL only (no SQLite for production)
- API routes: Return proper HTTP status codes and error messages
- Markdown: Standard markdown syntax, frontmatter in YAML format
- Keep it simple — this is a cosmetician's website, not Medium.com
